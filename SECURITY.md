# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| latest on `main` | ✅ |

## Reporting a Vulnerability

Если вы обнаружили уязвимость, откройте
[GitHub Security Advisory](https://github.com/burovgena-eng/atlas-hookah/security/advisories/new)
вместо публичного issue.

Пожалуйста, включите в отчёт:

- описание уязвимости и её влияние;
- шаги воспроизведения (PoC-код и скриншоты приветствуются);
- затронутые эндпоинты / файлы.

Ожидаемый срок первого ответа — 72 часа.

## Security Architecture

- **Сессии.** Серверные сессии с 256-битными токенами (`X-Session-Token`); в БД
  хранится только SHA-256 хеш. Актор для всех операций определяется
  исключительно сервером по сессии, а не переданными клиентом ID.
- **Пароли** хешируются PBKDF2-SHA512 (10 000 итераций, случайная соль);
  сравнение — timing-safe. Поддерживается миграция со старого формата.
- **Авторизация** ролевая (MANAGER, SENIOR_MASTER, ADMIN, HOOKAH_MASTER);
  проверка прав на каждом маршруте; self-escalation роли заблокирован.
- **Валидация** всех входных данных (`src/lib/validation.ts`): длины строк,
  форматы (email, телефон, URL, cuid), whitelist'ы enum'ов и ролей.
- **Rate limiting**: вход 5/мин (блок 15 мин), регистрация 3/час,
  уведомления 10/мин, загрузки 20/мин.
- **Загрузка файлов**: MIME + magic numbers + whitelist расширений,
  криптостойкие имена, защита от path traversal при отдаче файлов.
- **Журналирование** событий безопасности в `logs/` с уровнями severity.

## Known Limitations (demo)

- Rate limiting, CSRF и хранилища сессий — **in-memory**: при масштабировании
  на несколько инстансов требуется Redis/БД.
- Токен сессии хранится в localStorage (XSS на клиенте может его прочитать).
  Для продакшена рекомендуется перенос в httpOnly cookie.
- `/api/seed` создаёт демо-аккаунты с известным паролем на пустой базе —
  в публичном деплое его следует удалить или закрыть.

## Deployment Notes

- **SQLite** хранит все данные в одном файле. Никогда не коммитьте `db/*.db`
  и `prisma/*.db` — `.gitignore` уже исключает их; демо-данные создаются
  скриптом `/api/seed`.
- Смените демо-пароли перед публичным запуском.
